## Project Overview

hyzero — a chess engine emulating MuZero. Rust core (game logic, MCTS, self-play
coordinator) with a Python neural network layer (PyTorch models) bridged via PyO3.

## Commands

```bash
# Build
cargo build

# Test
cargo test                   # Rust tests (89 total: 82 pass, 7 ignored)
cargo test --release -- --ignored  # + slow perft and Python-dependent tests
python3 scripts/cross_validate.py --all  # vs python-chess oracle
cd python && pytest          # Python tests
bash scripts/e2e_test.sh     # End-to-end validation

# Lint/Format
cargo clippy
cargo fmt

# Run
cargo run                    # main binary
cargo run --bin server       # game server
cargo run --bin client       # client
cargo run --bin selfplay     # self-play training loop
cargo run --release --bin perft -- <FEN> <depth>  # perft CLI

# Baseline
bash scripts/run_baseline.sh 1800    # 30-min training run, outputs score to logs/baseline_score.json
```

## Architecture

- `src/pieces/` — piece move generation (bishop, king, knight, pawn, queen, rook)
- `src/game/` — board state, game history, player abstraction
- `src/mcts/` — Monte Carlo Tree Search (node, tree, PUCT selection, evaluator)
- `src/selfplay/` — self-play coordinator, inference backend, training data pipeline
- `src/data/` — board encoding, replay buffer, data types
- `src/session/` — game session management
- `src/py/` — PyO3 bridge to Python (inference backend, training)
- `src/bin/` — binary entry points (server, client, selfplay)
- `python/hyzero/` — Python MuZero model definitions and config

## Key Dependencies

- **pyo3** + **numpy** — Rust↔Python FFI for neural network inference
- **tokio** — async runtime for server/client and self-play coordination
- **serde** + **bincode** — serialization for game state and replay data
- **rand** — randomness for MCTS and game simulation
- **torch** (Python) — neural network training and inference
