### [MEDIUM] PGN game numbers collide across pool opponents within a cycle

- **Location:** `src/selfplay/evaluation.rs` around lines 422-465
- **Failure:** With `pool_size=3` and `gps=4`, each opponent's white-side loop uses `game_idx + 1` (1..=4) and black-side loop uses `gps + game_idx + 1` (5..=8). These indices reset per opponent iteration, so a single eval cycle emits three distinct games all headed `[Event "Eval Cycle N Game 1"]`, three headed `Game 2`, etc. Standard PGN parsers (chess.com importer, python-chess) treat these as duplicates or lose the pairing between game and opponent version tag. Only the white/black label strings (`pool v{opponent_version}`) disambiguate — the `[Event]` tag does not.
- **Fix hint:** Track a running `game_num` counter across the whole `'pool_loop` (or fold `opponent_version` / an opponent index into the Event name) so each written game gets a unique cycle-scoped number.
