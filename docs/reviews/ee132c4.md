## Findings

### Bugs / real concerns

1. **`tablebase.py` `sample()` is always with-replacement once `n >= len(pool)`.**
   `python/hyzero/data/tablebase.py:182-200` — the branch
   `if n >= len(pool): random.choices(pool, k=n)` silently switches to
   _with-replacement_ even at `n == len(pool)`. Callers that pass `n == len(pool)`
   (e.g., draining the cache once) will get duplicates and miss real entries.
   Use `random.sample(pool, len(pool))` for the `n == len(pool)` boundary.

2. **`HYZERO_REINIT_VALUE_BIAS` parse aborts checkpoint load on bad input.**
   `python/hyzero/training/trainer.py:368` — `float(os.environ.get(..., "0.0"))`
   raises `ValueError` on a typo, killing checkpoint resume instead of falling
   back. Other env-var parses in this file use try/except; this one should too.

3. **`_reinit_value_head` uses kaiming with `nonlinearity='linear'`.**
   `python/hyzero/training/trainer.py:381` — gain=1.0. The value head is `tanh`,
   for which the standard gain is `xavier_normal_` or `kaiming_normal_(nonlinearity='tanh')`
   (gain ≈ 5/3). The collapsed-attractor escape may be weaker than intended.

4. **Snapshot TB samples without `mating_actions` get reward=0 at step 1 but
   value=±1 at step 0.**
   `python/hyzero/data/tablebase.py:278-280` — only fires reward when
   `mating_actions` is non-empty. Combined with `is_tablebase=True` masking
   (which zero-masks steps 1..K everywhere except the reward at k=1), this
   means winning-but-not-mate-in-1 positions contribute **zero reward signal**
   while still emitting a value=+1 target. If most of the cache is non-mate-in-1
   (likely, since DTZ>1 dominates), the headline goal of "supplying the reward
   head with terminal-transition examples" is largely unrealized.

5. **PGN writer concurrent interleaving.**
   `src/selfplay/pgn.rs` (pre-existing, newly exercised) — `write_pgn_game` is
   called concurrently from multiple self-play tasks at 1% sample rate. It does
   `OpenOptions::append(true)` then issues many small `writeln!` syscalls on a
   raw `File`. POSIX append is atomic per-`write()` but not across the 5+
   `writeln!`s. Two games can interleave headers and move lines → unparseable
   PGN. Wrap writes in a single buffered string and emit one `write_all`.

6. **Diverse-start FENs begin with empty history buffer.**
   `src/selfplay/game_task.rs:172-201` (and `play_game_dual` analogue) —
   `init_self_play_board` returns `(board, side_to_move)` but the
   `VecDeque<BoardSnapshot>` history is freshly empty in both play loops. For
   the 70% of FENs that are middlegame or endgame, the network sees
   zero-filled past-7-ply history planes for positions that look mid-game.
   Either seed history with `BoardSnapshot::from(&board)` repeated, or skip
   history planes for diverse-start games (signaled per-trajectory).

7. **`tb_indices` set is computed but unused.**
   `python/hyzero/training/trainer.py:534` — dead code; only `is_tb_mask` is
   consumed downstream. Not a correctness bug but worth removing to reduce
   noise.

### Lower-severity / subtle

8. **Reward-loss path at `k == 1` does not mask TB rows.**
   `python/hyzero/training/trainer.py:632-637` — the `k == 1` branch uses
   `per_sample_rwd.mean()` over the whole batch, justified by "TB step-1
   reward carries the real mating-action signal." This is true _only_ for TB
   snapshot rows with `mating_actions` non-empty (see finding #4). Rows
   without mate-in-1 contribute a silent zero target into the mean, diluting
   the signal from replay rows. Either mask zero-reward TB rows or store an
   explicit `has_reward_target` flag.

9. **Consistency-loss denominator includes skipped TB step.**
   `python/hyzero/training/trainer.py:829-836` — when _all_ batch rows are TB,
   `cos_sim.numel() == 0` is correctly skipped, but the per-step divisor
   `k_steps` still counts the skipped step → under-weighted. Edge case;
   batches are usually a mix.

10. **Absorbing-step action plane is zero (`build_tb_batch_trajectories`).**
    `python/hyzero/data/tablebase.py:343` (np.zeros init) — past the mate step
    the trajectory's `actions[k] == -1` sentinel ends up encoded as an
    all-zero `[3,8,8]` plane. With `is_tablebase=False` the consistency loss
    is active, pulling `g(h_{k-1}, zero_action)` toward `h(zero_obs)` —
    training the dynamics head to map zero-action → empty-board representation.
    Probably benign but worth a regression check.

11. **Reward-target POV/index convention for self-play vs TB snapshot.**
    Cross-cutting (`game_task.rs:539-541` ↔ `tablebase.py:278-280`). Self-play
    sets `last.reward = game_outcome * last_side_sign` _on the last recorded
    StepRecord_ (which is the mating-action step, not an absorbing successor).
    The TB snapshot builder puts `+1.0` at the absorbing index `target_rewards[1]`.
    The trainer's unroll consumes `actions[k-1]` and predicts `target_rewards[k]`
    so the TB convention aligns with "reward of action a*{k-1}", whereas the
    self-play convention attributes the mating reward to the action *before*
    the mating move (action a*{K-1}) — and in the opposite-color POV.

    This is a _pre-existing_ self-play convention (commit `773cb90`, not
    introduced here), but the new TB infra now exposes the mismatch in a
    batch that mixes both. Worth confirming with a unit test that, for a known
    Black-mates self-play trajectory, the reward head learns the correct sign
    at the correct unroll step. If not, the self-play `last.reward` placement
    should move to an explicit absorbing successor step (cost: one extra
    StepRecord per game).

### Verified clean

- `src/mcts/tree.rs` canonical backup `G_{k-1} = r_k − G_k`: math correct, POV
  storage correct, degenerates to prior behavior when all edge rewards are
  zero (existing tests pass bit-for-bit by inspection).
- `src/data/encoding.rs` flip invariant: holds for all 4672 action indices
  including 576 underpromotions and illegal padding slots (`to_file ≥ 8`).
  Python mirror in `board_encoder.py` matches Rust line-for-line.
- `src/py/training.rs` color-aug POV: `flip_sign * step.root_value` and
  `flip_sign * sample.game_outcome * original_root_side_sign * ply_flip`
  consistent for arbitrary starting side (handles `Color::Black` diverse
  starts).
- `OnceLock<Vec<String>>` for STARTS FEN list is race-free; empty / unset
  env var falls back to the standard start; bad FENs log and fall through.
- `legal_actions.sort_unstable()` happens BEFORE `MCTSTree::new` and BEFORE
  `StepRecord { legal_moves, .. }`, so child-slot ↔ action correspondence
  stays consistent. Regression test pins it.
- Random tie-break in `select_action` collects ALL tied indices and samples
  uniformly per the project rule.
- TB cache `__main__` shim restore is exception-safe (try/finally).
- Trainer diagnostic block is fully wrapped in try/except — no risk of
  aborting training on a logging error.
- Probe positions (`kqk_obs`, `kvk_queenless_obs`) match
  `_build_start_obs` plane convention.

## Suggested next steps (priority order)

1. Add a unit test that, for a Black-mates self-play trajectory of length T,
   `g(h_{T-2}, encode(steps[T-1].action))` is trained against the mating
   reward in the **correct mover POV**. If it fails, fix
   `game_task.rs::last.reward` placement (see finding #11).
2. Fix `sample()` with-replacement boundary (finding #1).
3. Wrap the TB cache rebuild so snapshot rows without `mating_actions` either
   (a) are excluded from the cache, or (b) signal "no reward target" so the
   k=1 loss path can mask them (findings #4 + #8).
4. Wrap concurrent PGN writes in a single `write_all` (finding #5).
5. Decide history-buffer policy for diverse starts (finding #6).
6. Harden `HYZERO_REINIT_VALUE_BIAS` parse (finding #2).
7. Switch reinit gain to tanh (finding #3).
