# Review: ee132c4 — TB supervision + canonical backup + diverse starts

Bug-focused review of the squashed commit `ee132c4` (~62k LOC, mostly logs

- PGN data). Read scope: substantive Rust + Python under
  `src/`, `python/hyzero/`, `python/tests/`. Bulk log / pgn / docs skipped.

Severity legend: **H** = correctness or runtime hazard,
**M** = subtle correctness or efficiency issue,
**L** = code-quality / cosmetic.

## H1 — Debug probe writes to `/tmp` on every train_batch call (`python/hyzero/training/trainer.py:651-657`)

```python
try:
    with open("/tmp/hyzero_diag_probe.txt", "a") as _pf:
        _pf.write(f"[diag_reached] step={self.model_version}\n")
        _pf.flush()
except Exception:
    pass
_diag_print(f"[diag_reached] step={self.model_version}")
```

This append-mode write runs unconditionally on **every** `train_batch` call
(many thousands per training run). It has:

- no rotation, no cap, no env-gate;
- duplicates the immediately-following `_diag_print` to stdout;
- writes to `/tmp` which is shared / size-limited on many hosts.

A long-running training session will fill `/tmp` and degrade unrelated
processes on the same machine. This is leftover instrumentation from the
diagnostic-investigation arc and should be deleted (or at minimum gated
behind an env var and rotated). The `_diag_print` line right after it
already provides the same signal via stdout/stderr.

**Fix**: delete lines 651-657, keep the `_diag_print` call.

## H2 — Temperature-sampling overflow silently degrades to first-index argmax (`src/mcts/tree.rs:609-628`)

```rust
let inv_temp = 1.0 / temperature;            // 0.01 -> 100.0
let weights: Vec<f32> = visits.iter().map(|&v| v.powf(inv_temp)).collect();
let total: f32 = weights.iter().sum();
...
let threshold = rand::random::<f32>() * total;
let mut cumulative = 0.0;
for (i, &w) in weights.iter().enumerate() {
    cumulative += w;
    if cumulative >= threshold { return self.root.legal_actions[i]; }
}
```

Both `play_game_dual` (eval games, always `0.01`) and `play_game` self-play
after `temperature_moves` (also `0.01`) call `select_action(0.01)`. With
visit counts ≤ `num_simulations` (default 800), `v.powf(100.0)` overflows
to `+inf` for any modestly-visited child (`50^100 ≈ 1e170 > f32::MAX`).

Result: every visited child becomes `+inf`, total = `+inf`, threshold =
`+inf`, and the loop returns the **first** non-zero-visit index because
`+inf >= +inf` is true. The advertised "near-greedy with stochastic
tie-break" silently degenerates to "deterministic argmax with
first-index tie-break."

Combined with `legal_actions.sort_unstable()` (the new color-symmetry
fix), eval games are now **fully deterministic** for a given starting
FEN — the only diversity comes from `HYZERO_STARTS_FILE`. Self-play
after move 30 also loses tie-break randomness, though Dirichlet root
noise still varies move-to-move.

This is functionally a regression: the explicit-`temperature ≤ EPSILON`
deterministic branch (lines 585-608) does proper random tie-breaking, and
the temperature path was clearly meant to be slightly noisier than that.
With overflow it's strictly less noisy.

**Fix options** (pick one):

1. Treat `temperature` ≤ some small threshold (e.g. 0.1) as the
   deterministic-with-random-tiebreak branch.
2. Compute weights in log-space:
   `log_w = inv_temp * v.ln()`, then `softmax` after subtracting max
   (`log_w_max`), giving a well-conditioned categorical distribution.
3. Clamp `inv_temp` (e.g. `inv_temp.min(20.0)`) so `v.powf(...)` stays in
   `f32` range for `v ≤ 800`.

Option 2 is the standard fix and matches AlphaZero/MuZero implementations.

## M1 — Consistency loss division when all rows are TB-masked (`python/hyzero/training/trainer.py:830-836`)

```python
if is_tb_tensor is not None:
    cos_sim = cos_sim[~is_tb_tensor]
if cos_sim.numel() > 0:
    consistency_loss = consistency_loss + (1 - cos_sim.mean())
if k_steps > 0:
    consistency_loss = consistency_loss / k_steps
```

If a batch happens to be 100% TB-snapshot rows (possible if `tb_frac`
≥ 1.0 or replay buffer is empty), every step's `cos_sim` is filtered to
`numel == 0`, the inner `if` skips, and `consistency_loss` stays at
`tensor(0.0, requires_grad=False)` — but is then divided by `k_steps`.
That divide is harmless on a no-grad zero, but the contract "consistency
loss is averaged over K steps" silently breaks: the result is `0`
regardless of what the dynamics network is doing on the (zero) TB rows.

This is mostly cosmetic — TB-snapshot consistency exclusion is
intentional — but worth a comment so a future reader doesn't assume the
reported `consistency_loss` of 0.0 means perfect prediction.

**Fix**: add a comment, or convert the divide to an `if any_step_contributed`
check.

## M2 — `_maybe_mix_tb_samples` placeholder mask weakens replay policy gradient (`python/hyzero/training/trainer.py:980-986`)

```python
else:
    placeholder = np.ones((b - n_tb, tb_dict["legal_masks"].shape[1]), dtype=bool)
    merged["legal_masks"] = np.concatenate(
        [placeholder, tb_dict["legal_masks"]], axis=0
    )
```

When the replay batch has no `legal_masks` (the older path) but TB is
active, the trainer fabricates an all-True mask for replay rows. With the
mask present, `_policy_loss` _applies it_ and the cross-entropy still
masks-fill `-inf` for `~mask` (none, since all True). Behaviorally
equivalent to "no mask," so this is OK. But the comment in the trainer
says masks are present — at this point `legal_masks` is _always_ present,
which is a contract the caller may not realize. If anyone later assumes
"mask present ⇒ correctly tight," they'll be wrong on TB-active+legacy-
replay batches.

**Fix**: emit replay legal masks unconditionally upstream (in
`assemble_batch_arrays`), so the placeholder branch becomes dead code
and can be deleted.

## M3 — `_reinit_value_head` env-var UX trap (`python/hyzero/training/trainer.py:352-393`, called at `:1058`)

`HYZERO_REINIT_VALUE_HEAD=1` calls `_reinit_value_head(self.f)`. Inside,
`HYZERO_REINIT_VALUE_BIAS` controls the offset; if **unset**, default is
`0.0`, so `_reinit_value_head` reinitializes weights to Kaiming-normal
and bias to 0.0 — `tanh(0) = 0`, exactly the collapsed value the user
intends to escape. The commit message says reinit "breaks value-head
distributional collapse" but only when both env vars are set.

**Fix**: either default `HYZERO_REINIT_VALUE_BIAS` to `0.3` when reinit
is enabled, or warn at startup that bias=0.0 won't escape collapse.

## M4 — Dead code + degenerate sample in Dirichlet sampler (`src/mcts/tree.rs:188-210`)

```rust
let y_gamma = loop {
    let x: f32 = rng.random::<f32>() * 6.0 - 3.0; // rough normal approx
    let u1: f32 = rng.random::<f32>();
    ...
    if v <= 0.0 {
        let _ = x; // suppress unused warning
        continue;
    }
    ...
};
```

(a) `x` is generated and never used; the `let _ = x;` admits this. Each
loop iteration wastes one RNG call (and cycles through `rng.random::<f32>()`
4 times instead of 3). Cosmetic but odd.

(b) If `u1 == 0.0` (probability ≈ `2^-32`), `u1.ln() = -inf` propagates
through to `y_gamma = +inf`. After the multiplicative `* u^(1/alpha)`,
`samples[i] = inf`. The normalization branch is `if sum > 0.0`, which is
true for `+inf`, so every sample divides by `inf` → all zeros. Then the
caller does `(1-ε) * prior + ε * 0 = (1-ε) * prior` and **does not
renormalize**, so the priors sum to `1 - ε` instead of 1 for that single
move. PUCT uses priors as ratios so this isn't catastrophic, but it's a
silent inconsistency with the rest of the codebase that assumes priors
sum to 1.

**Fix**: remove `x`; clamp `u1.max(f32::MIN_POSITIVE)` before `ln()`; or
detect `samples.iter().any(|s| !s.is_finite())` and fall through to the
uniform path.

## M5 — Reward loss at `k=1` is unmasked over TB+replay (`python/hyzero/training/trainer.py:631-637`)

```python
if k >= 2:
    total_reward_loss = total_reward_loss + (per_sample_rwd * non_tb).sum() / non_tb_count
else:
    # k == 1: TB step-1 reward carries the real mating-action signal.
    total_reward_loss = total_reward_loss + per_sample_rwd.mean()
```

For TB **snapshot** rows, this is correct: `tgt_rewards[:, 1] = +1`
encodes the mating transition and we want it to contribute. For TB
**trajectory** rows, all rows have `is_tablebase=False`, so non_tb is
all-ones and the `else` branch is reached only when `is_tb_tensor` is
None or non_tb-mask happens to mask nothing — i.e. trajectory format
behaves identically to no-TB regardless of which branch is taken. Fine.

But: when snapshot TB rows are mixed with replay rows, the replay rows
contribute their (often noisy) `step.reward` (typically 0 except final
step) to the same averaged loss as the +1 TB targets. The TB signal-to-
noise here depends on `tb_frac`. The comment claims "TB step-1 reward
carries the real signal" — true, but with `tb_frac=0.1` only 10% of the
batch carries +1 and 90% contributes ~0. The mean is dominated by the
replay rows, diluting the TB signal exactly where the trainer is trying
to lean on it.

This isn't a bug per se but is at odds with the design intent. Consider
either separating per-row reward losses (TB-only k=1 mean, replay-only
k=1 mean, weighted) or upweighting `tb_frac` proportionally.

## M6 — `play_game_dual` evaluators see `add_root_noise: false` but evaluators may still differ stochastically (`src/selfplay/game_task.rs:253-257`)

Eval games disable Dirichlet noise. Combined with H2 (overflow → first-
index argmax) and the new sorted-legal-actions invariant, two
evaluators producing identical priors and values will produce **byte-
identical eval games**. This means:

- If challenger and champion are the same network at the same version,
  `eval_games_per_side=4` produces 4 identical games.
- If they differ in a way that doesn't change the top visit count's
  first-index (e.g. equally-good moves), eval may not detect the
  difference.

The intent of running multiple eval games per side is to build a
statistical signal. Without **any** randomness in eval (no noise, no
tie-break, deterministic start FEN sampling reseed-able by the rng),
this is partly defeated. Ensuring `select_action` keeps a small amount
of stochasticity (per H2 fix) restores the variance.

## L1 — `_diag_print` channel order may double-write (`python/hyzero/training/trainer.py:27`)

The fallback chain tries `sys.stdout`, `sys.__stdout__`, `sys.stderr`,
`sys.__stderr__` in order; first that succeeds, returns. Fine for
correctness, but if PyO3 wraps stdout in a buffer that swallows writes
silently (no exception), the line never reaches the screen and never
fires the fallback. If this is a concern, use `os.write(1, ...)` first.

## L2 — `_diag_print` invoked even when no diagnostic interval triggers (`python/hyzero/training/trainer.py:699-701`)

The per-`k` `val_stats` / `reward_stats` / `policy_stats` lines are
emitted on every `train_batch` (not just every 50 steps as `sym_probe`,
`tgt_hist`, etc. are). With `k_steps + 1 = 6` steps × 3 lines × every
step, this is ~18 lines per training step. Over a 30-min run that's
many MB of stdout. Consider gating on `model_version % N == 0`.

## L3 — Trace file truncation race (`src/mcts/tree.rs:74-89`, `src/selfplay/game_task.rs:32-44`)

Both `mcts_trace.log` and `mcts_summary.log` are opened with
`truncate(true)` from the first thread to call. Subsequent threads
short-circuit. Fine — but if the first writer crashes after creating
the file but before writing, subsequent writers re-enter
`get_or_init` once with no recovery. `OnceLock` semantics make this
non-fatal (re-entry returns the same Mutex<Option<...>>) but odd.
Cosmetic.

## L4 — `dirichlet_noise` extra Box-Muller cosine path (`src/mcts/tree.rs:191-193`)

Box-Muller produces TWO normal samples per pair of uniforms (cos and
sin). The code throws away the sin output. Each loop iter then does
1 `ln`, 1 `sqrt`, 1 `cos`, 1 `powi(3)`. For `n=4672` priors × 800 sims
× many games, this isn't free. Cosmetic, but a `rand_distr::Gamma`
dependency would replace the whole 30-line block.

## Summary

Two real bugs to fix soon:

1. **H1**: delete the `/tmp/hyzero_diag_probe.txt` writer in
   `trainer.py:651-657` — disk-fill hazard on long runs.
2. **H2**: replace `temperature=0.01` weight computation with log-space
   softmax (or treat near-zero temperature as the deterministic branch).
   Eval games are silently fully-deterministic right now.

Several **M** items worth a follow-up commit. Most are subtle correctness
or signal-quality issues, not crashes. The major fixes in this commit
(canonical backup, color-symmetric legal-action ordering, color-aug
sign correction, TB supervision routing) all look right based on the
test set and inline comments.
