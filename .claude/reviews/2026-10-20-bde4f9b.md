## Minor concerns (not defects)

1. **Misleading WARN on normal bootstrap** — `src/selfplay/evaluation.rs:278-280`. Pool-exclusion of the current champion makes bootstrap run on BOTH cycle 1 AND cycle 2 (after first promotion only `best_v001.pt` exists → gets excluded → pool empty → bootstrap again). The WARN labels this normal transitional state as "unexpected archive deletion". `docs/plans/elo-promotion/plan.md:189` also calls bootstrap "single-shot" when it is effectively two-shot. Behavior is correct, labeling is not.
2. **Asymmetric inequality operators in promotion gate** — `src/selfplay/evaluation.rs:531` uses `>=` for win_rate while `:533` uses `>` for Elo. Floating-point edge: a candidate landing *exactly* on the Elo threshold would be gated out while the win-rate check at its threshold passes. Pick one convention.
3. **Duplicated PGN "Round" numbers across pool members** — `game_idx + 1` and `gps + game_idx + 1` reset per opponent in the pool loop, so games from different pool members in the same cycle share Round numbers; disambiguated only by event/player label strings. PGN parsers keying on (Event, Round) may collapse games.
